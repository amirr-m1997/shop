در پروژه Django تست‌های Business Flow واقعی فروشگاه را بررسی و تکمیل کن.

هدف:
اطمینان از سالم بودن مسیرهای حیاتی خرید، پرداخت، سفارش و حساب کاربری بعد از تغییرات امنیتی و Performance.

مهم:

* تست‌ها باید رفتار واقعی کاربر را پوشش دهند.
* فقط تست unit ساده اضافه نکن.
* API contract، status code و رفتار فعلی نباید تغییر کند.
* اگر flow فعلی باگ دارد، ابتدا گزارش کن و بدون تأیید تغییر behavior نده.

---

# 1) Authentication Flow

سناریوهای کامل را تست کن:

## Register

بررسی:

* ثبت‌نام موفق
* ثبت‌نام با ایمیل تکراری
* ثبت‌نام با ایمیل مشابه ولی با case متفاوت
* validation خطا
* ایجاد صحیح profile/user data

## Login

بررسی:

* ورود موفق
* رمز اشتباه
* کاربر lock شده
* rate limit
* ثبت login history
* ثبت درست security event
* token/session بعد از login

## Password Flow

تست کن:

* درخواست reset password
* تایید token
* تغییر رمز
* رمز قبلی invalid شود
* sessionهای قبلی طبق سیاست پروژه رفتار کنند

---

# 2) Guest Order Flow

با توجه به مشکل امنیتی قبلی، تست‌های کامل اضافه کن:

سناریو:

Guest user:

* محصول اضافه می‌کند
* سفارش ایجاد می‌کند
* پرداخت انجام می‌دهد یا وضعیت pending می‌شود

سپس:

User account ایجاد می‌شود.

بررسی:

* سفارش فقط در شرایط مجاز منتقل شود.
* انتقال فقط با مکانیزم امن فعلی انجام شود.
* کاربر دیگر نتواند سفارش را claim کند.
* اطلاعات سفارش، پرداخت و آدرس محافظت شود.

تست regression برای جلوگیری از برگشت آسیب‌پذیری قبلی اضافه کن.

---

# 3) Cart Flow

سناریو:

کاربر:

* محصول اضافه می‌کند
* تعداد را تغییر می‌دهد
* محصول حذف می‌کند
* قیمت نهایی محاسبه می‌شود

بررسی:

* موجودی کافی
* محصول غیرفعال
* variant اشتباه
* cart merge بعد از login
* cart مهمان و cart کاربر

---

# 4) Checkout Flow

تست کامل:

* ایجاد checkout
* انتخاب آدرس
* انتخاب روش ارسال
* محاسبه هزینه ارسال
* اعمال تخفیف
* محاسبه مبلغ نهایی

بررسی:

* قیمت از سمت server محاسبه شود.
* client نتواند مبلغ را دستکاری کند.
* order با داده صحیح ساخته شود.

---

# 5) Payment Flow

سناریوها:

* پرداخت موفق
* پرداخت ناموفق
* callback تکراری
* callback جعلی
* transaction تکراری

بررسی:

* یک پرداخت دوبار ثبت نشود.
* وضعیت order درست تغییر کند.
* موجودی دوبار کم نشود.
* email notification درست trigger شود.

---

# 6) Inventory Flow

بررسی:

* کاهش موجودی بعد از سفارش موفق
* جلوگیری از موجودی منفی
* سفارش همزمان برای آخرین موجودی
* rollback در پرداخت ناموفق

اگر transaction یا locking وجود دارد، تست concurrency مناسب اضافه کن.

# 7) Discount / Coupon Flow

تست:

* کد معتبر

* کد محدود به کاربر
* استفاده چندباره
* حداقل مبلغ خرید
* تغییر قیمت بعد از اعمال تخفیف

# 8) Wishlist Flow

بررسی:

* افزودن محصول
* حذف محصول
* محصول تکراری
* دسترسی بدون login
* داده کاربر دیگر قابل مشاهده نباشد

مثلاً:

cancelled

# 10) Email / SMS Delivery Flow

بررسی:

* ایجاد DeliveryAttempt
* موفقیت ارسال
* شکست ارسال
* retry
* ثبت error
* جلوگیری از گزارش موفقیت جعلی

---

# 11) تست Regression بعد از Refactor

تمام flowهای مهم را بعد از refactor اجرا کن.

بررسی کن:

* URLها تغییر نکرده‌اند.
* serializerها تغییر نکرده‌اند.
* permissionها حفظ شده‌اند.
* status codeها تغییر نکرده‌اند.

---

# 12) کیفیت تست‌ها

از ابزارهای مناسب استفاده کن:

Backend:

* APIClient
* TransactionTestCase برای flowهای چندمرحله‌ای
* assertNumQueries در بخش‌هایی که performance مهم است

برای داده:

* factory یا fixture استاندارد پروژه

از تست‌هایی که فقط implementation را قفل می‌کنند خودداری کن.

---

# 13) گزارش نهایی

در پایان گزارش بده:

* تعداد تست‌های جدید
* flowهای پوشش داده شده
* فایل‌های تست ایجاد یا تغییر یافته
* نتیجه اجرای تست‌ها
* سناریوهایی که قبلاً پوشش نداشتند
* باگ‌هایی که در حین تست پیدا شدند

همچنین مشخص کن:

* چند تست integration اضافه شد
* چند تست regression امنیتی اضافه شد
* آیا مسیر کامل خرید از محصول تا سفارش موفق تست شده است یا خیر
